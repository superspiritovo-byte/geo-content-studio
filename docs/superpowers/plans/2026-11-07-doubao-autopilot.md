# 豆包自动运营闭环实施计划

已确认首个平台为豆包网页端，自动诊断、生成、复测和报告；发布继续人工确认。

1. 持久化自动运营配置、运行与周报。每个对比项目关联资料库，1—5 个固定无品牌问题，默认手动启用，每日最多一次自动周期，最多 2 篇草稿。每次运行冻结项目、资料和问题。
2. 工作进程复用现有单实例锁，顺序处理任务。运行状态、阶段和调用预算先落盘。重启后中断任务转人工处理，下一次周期仍有独立记录。采样失败可保留明细，但缺少完整样本不能生成诊断。
3. 豆包使用独立 Chrome 目录，与发布账号及日常浏览器隔离。打开登录窗口由用户完成登录。新对话、联网状态、发送及回答完成均需可核对控件。找不到唯一控件或遇验证时暂停。保留来源链接完整性标识，不能凭整个网页文本生成样本。
4. 真实采样先保存原文，配置的模型只对这些回答和选中资料诊断。品牌判定有原文引句，资料缺口为假设，事实依据只能引用输入资料。诊断返回有限内容任务，结构化生成沿用现有函数，保存草稿时不创建发布任务。
5. 同问题/入口/版本/联网/名单分组比较。自动判定与人工判定单独标注、统计。第一轮成功样本为基线，后续为复测，报告同时给出样本量与局限。自动周报由确定性程序汇总，可导出 JSON 和 Markdown，无样本也如实记录。
6. 增加自动运营页面，配置、登录、运行一次、启停、运行证据、草稿跳转与周报下载。费用以调用次数上限控制，启用前显示真实模型调用说明。资料解析为结构化事实候选，经用户确认后用于生成，不自动修改原资料。
7. 回归覆盖调度幂等、单项目互斥、日预算、重启、失败不伪造数据、诊断引句、知识隔离、草稿防重、周报幂等。独立数据目录验收，不对真实平台自动发文。

实施约定：
- 首版定时器在本机助手在线时工作，错过周期补跑一次，不补跑所有历史周期。
- 无法真实访问豆包时将页面接入与端到端采样标为待验收，不用 API 回答替代网页端样本。
