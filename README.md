# GEO 内容工作台

把企业资料整理成能回答客户问题的内容，再辅助发布到不同平台。

这是一个面向 GEO 内容运营场景的本地 AI 应用，支持企业资料管理、知识库问答、选题推荐、文章生成、富文本编辑和多平台辅助发布。使用 Next.js、React、TypeScript 和 SQLite 开发，可通过 Ollama 在本机完成向量检索与内容生成。

## 为什么做这个项目

企业介绍、产品说明和服务条款往往分散在不同文件中。写文章时，需要反复查资料、找选题、核对事实，再到各个平台编辑和发布。

这个项目将这些操作放在同一个工作台中：

```text
导入企业资料 → 建立本地索引 → 围绕客户问题选题
                              ↓
检索相关片段 → 生成草稿 → 人工核对与编辑 → 平台辅助填入
                                               ↓
                                     人工发布 → 记录与核验
```

## GEO 在哪里体现

项目围绕客户可能提出的问题组织内容，支持长文、FAQ、问答对和知识卡片；生成时使用所选企业资料，要求直接回答问题、不堆砌关键词，并将缺失事实列为待核对事项。

目前完成的是面向 GEO 的内容生产与辅助分发流程。尚未实现外部 AI 搜索的品牌提及、引用率监测和对照评估，没有经过验证的排名或获客提升数据。发布成功、本地检索命中，都不能作为外部 AI 搜索收录或推荐的证明。

## 已实现的功能

| 模块 | 能做什么 |
| --- | --- |
| 企业资料 | 导入 TXT、Markdown、DOCX 或粘贴文字；按资料库隔离，解析失败的文件不参与生成 |
| 本地 RAG | 文档分块、向量化、余弦相似度检索、资料问答与来源片段展示；资料或模型变化后需要重建索引 |
| 选题与写作 | 根据资料、读者及写作目的推荐选题，生成文章、FAQ、问答对和知识卡片 |
| 内容编辑 | 富文本编辑、Markdown 转换与导出、带格式复制；目标平台可能调整粘贴后的样式 |
| 模型配置 | 本机 Ollama 与在线 OpenAI 兼容接口，包含连接测试、上下文检查及错误提示 |
| Chrome 连接 | 通过扩展复用日常 Chrome，核对账号身份，辅助填入文章和图片 |
| 发布记录 | 保存逐账号内容快照，防止重复提交，分别记录自动核验和人工确认结果 |

平台适配范围包括知乎、百家号、搜狐号，以及小红书图文笔记、抖音图文、哔哩哔哩图文动态。不同平台支持程度受页面、登录状态和风控影响，不表示全部真实账号流程已验收；不包含视频制作与发布。

## 本地运行

需要 **Windows、Node.js 24+、Google Chrome**。使用本地模型还需安装 Ollama，并预留模型下载所需的磁盘空间。

```powershell
git clone https://github.com/superspiritovo-byte/geo-content-studio.git
cd geo-content-studio
npm ci
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

也可以双击 `start.cmd`。脚本检查依赖和构建，启动网页及工作进程后打开：

**http://127.0.0.1:18080**

服务仅监听本机。一键启动的服务在后台运行，关闭网页不会停止服务。启动异常可查看数据目录中的 `logs/`，排查时不要批量结束所有 Node.js 或 Chrome 进程。

### 配置本地模型

先安装并启动 [Ollama](https://docs.ollama.com/windows)，下载模型：

```powershell
ollama pull embeddinggemma
ollama pull qwen3:1.7b
```

1. 在企业资料页的本机 RAG 区域保存本机配置。
2. 添加资料，为选中的资料库建立索引。
3. 提问并查看检索片段，核对答案依据。
4. 若希望选题和文章也使用本地模型，勾选并保存“选题与写作使用本机 RAG”。

资料问答始终使用本机模型。启用本机写作后，相关资料仅发送给环回地址上的 Ollama，失败时不会自动切换云端；下载模型本身需要网络。取消本机写作后恢复在线接口流程，在线生成会发送所选企业资料给配置的服务商。

向量保存在 SQLite 中，小规模检索在应用内计算余弦相似度，无需部署独立向量数据库。每个资料库最多 2000 个片段；相似度分数不代表答案置信度。生成文章保留当时的检索片段快照，人工编辑后仍需核对事实。

### 连接日常 Chrome

1. 在“设置 → Chrome 连接”点击“打开扩展文件夹”。
2. 在 Chrome 打开 `chrome://extensions`，开启开发者模式，点击“加载已解压的扩展程序”，选择上述文件夹。
3. 在工作台生成配对码，打开工具栏中的“GEO 工作台 · Chrome 连接助手”，粘贴并连接。
4. 在发布账号页打开对应平台，自行登录并读取身份，核对后保存。

扩展默认连接 `http://127.0.0.1:18080`。它在现有 Chrome 中打开标签页，不为每个账号另开浏览器窗口。断线时暂停，不自动回退到独立浏览器；旧的独立会话模式仍可显式选择。更新扩展文件后，需要在扩展管理页重新加载。

### 写作和发布

1. 上传资料：每份资料最多 10 个文件，每个不超过 8MB；PDF 需先转换。
2. 在工作台选择资料、读者及写作目的，推荐选题或直接写文章。
3. 编辑草稿，人工核对价格、案例、数据和服务承诺。
4. 选择平台账号、封面或图文图片，确认内容后开始辅助准备。
5. 在平台页面检查格式、图片顺序及声明，完成最终发布。
6. 回工作台填写公开链接，检查结果或记录人工确认。

默认扩展模式下，所有平台的最终发布由用户完成。图片支持 PNG/JPEG/WebP，最多 9 张，每张不超过 8MB。平台控件不明确、已有草稿、账号身份不符或遇到验证码时会暂停。

## 发布核验与防重复

- 自动核验检查允许的公开链接、署名、标题与完整正文；无法取得充分证据时，不标记“已公开发布”。
- HTTP 403、登录墙和超时表示无法核验，不能据此判断仍在审核，也不应重复发布。
- “人工确认已发布”是用户自行核对后的记录，与自动核验结果分开展示。
- “已在平台处理完毕，释放账号”表示结束当前任务占用，让该账号可以处理下一篇内容，不会退出平台登录，也不代表自动核验成功。
- 每个账号保存不可变内容快照。通过事务、幂等标识及内容指纹防重，可能已经提交或已声明人工发布的任务不会自动重发。

## 数据存储与隐私

数据目录按以下优先级选择：`GEO_DATA_DIR` 环境变量 → 项目中的 `local-data.json` → `%LOCALAPPDATA%\GEOStudio\data`。网页与工作进程必须使用同一目录。

`local-data.json` 用于固定已有工作区，不随仓库提交。配置的数据文件缺失或工作区标识不一致时会停止启动，避免误开空白工作区；已有用户不要删除该文件或覆盖数据目录。

| 内容 | 保存位置 |
| --- | --- |
| 资料文本、向量、文章、账号元信息与发布记录 | `geo.sqlite` |
| 上传原文件 | `documents/` |
| 封面与图文图片 | `covers/` |
| 旧独立浏览器模式的登录会话 | `profiles/` |
| 运行日志 | `logs/` |

API 密钥通过 Windows 当前用户的 DPAPI 加密保存，不向前端返回完整密钥。扩展沿用 Chrome 自身登录状态，不导出日常浏览器 Cookie 或登录文件。

备份前先停止本项目网页和工作进程，再复制完整数据目录。换 Windows 用户或电脑后，可能需要重新填写密钥并登录平台。数据库、上传资料、会话和本机配置均不应提交到 Git。

## 技术实现

- **应用：** Next.js App Router、React、TypeScript。
- **存储：** Node.js 原生 SQLite，保存业务记录、检索索引与任务快照。
- **模型：** Ollama 本机嵌入与生成模型；可配置在线 Chat Completions 兼容接口。
- **浏览器：** Chrome Manifest V3 扩展、本机任务桥接；保留 Playwright 独立适配与核验代码。
- **任务：** 独立 Node.js 工作进程、心跳、超时处理与中断恢复。

开发过程中使用 Codex 辅助需求拆解、实现、排查与测试。

## 开发与验证

```powershell
npm ci
npm run dev
# 另一个终端启动工作进程
npm run worker
```

开发网页默认使用 3000 端口；扩展默认连接 18080，联调扩展时需使用匹配的服务地址。测试使用独立临时数据目录，不向日常工作区添加演示资料。

```powershell
npm test
npm run typecheck
npm run build
```

测试覆盖资料隔离、本地索引失效、模型响应校验、扩展配对、账号身份、内容快照、防重复提交、链接校验和格式转换。

可选验证入口：

- `tests/rag-real-smoke.ts`：显式运行真实本机模型验证，使用临时资料库。
- `tests/chrome-extension-smoke.mjs`：真实扩展与虚拟 HTTPS 平台页面的隔离验证，需要 Playwright Chromium；先使用 `GEO_BUILD_DIR=.next-chrome-qa` 构建。

单元测试、模拟页面和构建通过，不代表真实平台发布全部通过，更不代表 GEO 效果得到验证。Node.js 24 的 SQLite ExperimentalWarning 本身不表示操作失败。

## 当前范围

当前版本聚焦本地资料、内容生成、编辑与辅助发布。AI 推荐监测和自动运营已回退，未提供外部 AI 搜索引用率、曝光量或询盘转化统计。后续若开展 GEO 效果评估，需要固定问题集、重复采样并比较内容发布前后的引用情况。
